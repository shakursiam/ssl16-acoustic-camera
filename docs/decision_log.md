# Decision log

Every choice that affects a result in the paper is recorded here, so the Methods section can be written from it.
Status is one of: **decided** (Siam approved), **proposed** (waiting for Siam), **open**.

| # | Date | Topic | Decision | Reason | Status |
|---|---|---|---|---|---|
| 1 | 2026-11-17 | Recording rate | Campaign audio of record is raw 48 kHz, 16-bit, 16 channels, written to microSD by `SSL16_Rec48`. The 12 kHz USB stream is saved by the PC logger as a live copy and backup. | Full-speed USB cannot carry 1.536 MB/s. The 12 kHz path is filtered (flat to 4.5 kHz, −50 dB from 6 kHz), which would limit E0 channel-skew measurements and the 5–6 kHz band. | **decided** 2026-11-17 (Siam approved after the `test48b` SD pass). Results from the live 12 kHz path and from offline 48 kHz analysis are labelled separately in the paper. |
| 2 | 2026-11-17 | Channel order in files | All campaign WAV files are in TDM slot order (M2 M7 M10 M15 M1 M4 M9 M12 M3 M6 M11 M14 M5 M8 M13 M16), the order assumed by `MICS` in `ssl16_core.py`. | `SSL16_WavRecorder_v4.1` writes mic order (M1…M16) by default. Mixing the two conventions would scramble the geometry without any error. Any file from v4.1 must be remapped before analysis; the integrity checker will read the order from each run's `.txt`. | proposed |
| 3 | 2026-11-17 | Speed of sound | c = 331.3·sqrt(1 + T/273.15) m/s, T in °C from the logged temperature. Humidity is logged per session and its effect goes into the uncertainty budget. | This is the ideal-gas (dry air) form; the linear form 331.3 + 0.606·T in `ssl16_core.py` is its first-order approximation and differs by about 0.1% at 26 °C. Reference to check and cite: O. Cramer, J. Acoust. Soc. Am. 93(5), 2510–2516, 1993, doi:10.1121/1.405827 (located, not yet opened; do not cite until read). | proposed; `ssl16_core.py` not changed yet |
| 4 | 2026-11-17 | Run naming | The PC logger fixes the run ID when Measure is pressed and sends `START <run_id>` to the board, so the SD file and the PC file share one name. | Lets the 48 kHz SD file be matched to its metadata without manual bookkeeping. | implemented in logger rev 2.1, untested on hardware |

## Open items

- Tap test of the slot map: done by Siam on 2026-11-17, all 16 mics respond individually (reported, not yet checked from files). For claim C1 the tap recordings themselves are needed as evidence; location of the files to be confirmed.
- Array orientation / mirror check (E0.5): not done. No E1–E8 data is valid until it passes. Detailed procedure added to both lab guides on 2026-11-17 (physical UP/RIGHT labels, +θ = operator's right when facing the sound-hole face, points ORI_T45 / ORI_T-45 / ORI_P30, pass = correct sign and within 10°).
- Mic identification by blowing on each mic in turn (`blow16`, 60 s, M1→M16), 2026-11-17: **passes on the PC 12 kHz file** (mic order after the slot → mic map). The 16 blows appear in order M1, M2, …, M16 and in each one the blown mic is the loudest channel, with a 5–29 dB margin over the second loudest (M7 5.3 dB, M4 9.3 dB, others ≥ 15.9 dB; M15 ≈ 23–31 dB and M16 ≈ 21–36 dB in their strongest 0.25 s windows). A 0.1 s transient at t = 0 is not a blow. Around 51.5–53 s, M16 and M8 alternate as loudest; then M16 is clear. 2 USB packets were lost in this run (zero-filled). The SD copy (`blow16.wav`) was not in `day0_test`. Because test48b/test48c showed the SD file equals the PC stream bit-exactly, the map holds for the SD files too. This supports claim C1 together with Siam's individual tap test.
- `SSL16_Rec48` v1.2 verified with `test48c` (10 s): the `.txt` first_seq now gives the right offset to the PC file directly (3 packets), and all 16 channels match bit-exactly (max 1 LSB).
- SD card write speed (`SSL16_SDTest`): not measured.
- 2026-11-17 first `SSL16_Rec48` run (`test48`, 30 s): firmware boots and streams (USB 101 pkt/s, 0 lost; PC 12 kHz file clean, 2993 packets, no clipping, all 16 channels alive at −67 to −70 dBFS RMS in a quiet room). **SD path fails the Day 0 check:** SD run lasted 26 s; 2037 blocks dropped (≈ 20.4 s missing), SD file 9.7 MB (≈ 6.3 s of audio) instead of ≈ 40 MB, i.e. about 0.37 MB/s sustained against 1.54 MB/s needed. `SSL16_SDTest` on the same card then gave 4-bit 20 MHz, 29.8 GB SDHC/SDXC, write 6.13 MB/s, read 4.35 MB/s, verify PASS — so the card is fast enough. Cause: Rec48 v1.0 wrote straight from the PSRAM ring; the SD driver cannot DMA from PSRAM and falls back to single 512-byte sectors (SDTest uses an internal DMA buffer). Fixed in Rec48 v1.1 (copy through a 32 KB internal DMA buffer); v1.1 not yet compiled or tested. Decision #1 cannot be adopted until a v1.1 run shows ring_drop = 0.
- 2026-11-17 `test48b` (Rec48 v1.1, 30 s): **SD path passes.** 4bit_20MHz, internal DMA buffer, 3002 blocks, ring_dropped_blocks = 0, sd_errors = 0, i2s_overflows = 0, file 46,110,764 B = 44 B header + 1,440,960 frames × 32 B, no repeated blocks, no clipping, all 16 slots −72 to −75 dBFS RMS (quiet room, raw 48 kHz). Cross-check: the SD file passed through the firmware FIR and decimated by 4 equals the PC 12 kHz file (after mapping slot → mic) bit-exactly on 15/16 channels and within 1 LSB on M15 over 360,090 samples each, at a fixed offset of 720 samples (6 packets). This confirms no missing or reordered samples and that the SD slot order and the PC mic order agree. The `.txt` said first_seq 5 packets after the PC start (off by one block); fixed in v1.2 (not yet compiled). Board temperature 30.6 → 29.9 °C during the run.
- Analysis parameters (band, grid, frame length, bin selection) for 48 kHz input: to be fixed before any accuracy number is computed, and not tuned on the reported data.
